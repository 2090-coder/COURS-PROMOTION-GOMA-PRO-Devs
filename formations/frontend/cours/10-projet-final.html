WEB FRONTEND · CHAPITRE 10

Projet final professionnel

Mettre ensemble HTML, CSS, JavaScript, DOM, données, accessibilité, Git et déploiement pour construire une application réellement utilisable.

1. Sujet proposé

Créer une application de gestion de tâches pour une petite équipe.

2. Fonctionnalités obligatoires

  • Ajouter une tâche.
  • Afficher les tâches.
  • Marquer une tâche comme terminée.
  • Supprimer une tâche.
  • Afficher un compteur.
  • Valider les entrées.
  • Afficher les erreurs clairement.
  • Conserver les données pendant la session ou utiliser une source JSON/API.

3. Structure

projet-final/
├── index.html
├── css/style.css
├── js/app.js
├── data/taches.json
├── assets/
└── README.md

4. Exemple HTML de départ

<main>
  <h1>Mes tâches</h1>
  <form id="formulaire-tache">
    <label for="tache">Nouvelle tâche</label>
    <input id="tache" name="tache" required>
    <button type="submit">Ajouter</button>
  </form>
  <p id="message" aria-live="polite"></p>
  <ul id="liste-taches"></ul>
</main>

5. Exemple JavaScript

const formulaire = document.querySelector('#formulaire-tache');
const champ = document.querySelector('#tache');
const liste = document.querySelector('#liste-taches');

formulaire.addEventListener('submit', (event) => {
  event.preventDefault();
  const texte = champ.value.trim();
  if (!texte) return;

  const element = document.createElement('li');
  element.textContent = texte;
  liste.appendChild(element);
  formulaire.reset();
});

6. Accessibilité

  • Utiliser des labels.
  • Utiliser de vrais boutons.
  • Prévoir un texte d'état avec aria-live lorsque nécessaire.
  • Vérifier la navigation au clavier.
  • Conserver une structure de titres logique.

7. Responsive

Le projet doit rester utilisable sur téléphone, tablette et ordinateur.

8. Git

git init
git add .
git commit -m "Initialiser le projet final"
git branch -M main
git remote add origin URL_DU_REPOSITORY
git push -u origin main

9. Documentation

Le README doit présenter le projet, ses fonctionnalités, l'installation, l'utilisation, la structure et les technologies.

10. Tests avant livraison

  1. Ajouter une tâche valide.
  2. Essayer d'envoyer un formulaire vide.
  3. Terminer une tâche.
  4. Supprimer une tâche.
  5. Tester au clavier.
  6. Tester sur mobile.
  7. Tester après publication.

Évaluation / 100

  • Fonctionnalités : 30
  • HTML/CSS : 20
  • JavaScript/DOM : 20
  • Responsive/accessibilité : 10
  • Git/documentation : 10
  • Tests et présentation : 10

Livrable

Un repository propre, un README clair, une application fonctionnelle et une URL de démonstration.
