WEB FRONTEND · CHAPITRE 09

Architecture et qualité frontend

Apprendre à organiser un projet pour qu'il reste lisible, maintenable, testable et évolutif.

1. Séparer les responsabilités

HTML structure le contenu, CSS gère la présentation et JavaScript gère le comportement. Les données peuvent être séparées dans JSON ou récupérées par API.

2. Structure recommandée

mon-projet/
├── index.html
├── pages/
├── css/
│   └── style.css
├── js/
│   └── app.js
├── data/
│   └── donnees.json
└── assets/
    └── images/

3. Noms et fonctions

  • Choisir des noms explicites.
  • Éviter les fonctions gigantesques.
  • Une fonction doit avoir une responsabilité claire.
  • Éviter la duplication inutile.

4. Exemple HTML + CSS + JavaScript

<button id="btn" type="button">Ajouter</button>
<p id="compteur">0</p>

<script>
const btn = document.querySelector('#btn');
const compteur = document.querySelector('#compteur');
let nombre = 0;

btn.addEventListener('click', () => {
  nombre++;
  compteur.textContent = nombre;
});
</script>

Le HTML crée les éléments et JavaScript leur donne un comportement. En production, placer le JavaScript dans un fichier séparé.

5. Gestion des erreurs

try {
  const reponse = await fetch('data/donnees.json');
  if (!reponse.ok) throw new Error('Erreur HTTP');
  const data = await reponse.json();
} catch (erreur) {
  console.error(erreur);
}

6. Responsive

Tester plusieurs largeurs d'écran. Utiliser des unités flexibles, Flexbox, Grid et des media queries lorsque nécessaire.

7. Tests manuels

  1. Tester chaque bouton.
  2. Tester les formulaires valides et invalides.
  3. Tester le clavier.
  4. Tester les écrans mobiles.
  5. Tester les erreurs réseau.
  6. Vérifier la console du navigateur.

8. Qualité avant publication

  • Pas de lien cassé.
  • Pas d'image manquante.
  • Pas d'erreur JavaScript bloquante.
  • HTML correctement structuré.
  • CSS organisé.
  • README présent.
  • Projet versionné avec Git.
