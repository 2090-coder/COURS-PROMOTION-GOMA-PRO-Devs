WEB FRONTEND · CHAPITRE 08

Git, GitHub et déploiement

Apprendre à enregistrer l'évolution d'un projet, revenir en arrière, collaborer et publier un site.

1. Pourquoi Git ?

Git est un système de gestion de versions. Il garde l'historique des modifications du projet.

2. Installer et vérifier Git

Après installation, ouvrir le terminal :

git --version

Si une version apparaît, Git est disponible.

3. Créer un dépôt local

mkdir mon-site
cd mon-site
git init
git status

4. Premier commit

git add .
git status
git commit -m "Premier commit"

add prépare les fichiers, commit enregistre un point de l'historique.

5. Consulter l'historique

git log --oneline

6. Modifier puis enregistrer

git status
git diff
git add .
git commit -m "Ameliorer la page d'accueil"

7. Branches

git branch
 git switch -c nouvelle-fonctionnalite
 git switch main

Une branche permet de travailler sur une évolution sans modifier directement la branche principale.

8. GitHub

Créer un repository GitHub puis relier le dépôt local :

git remote add origin URL_DU_REPOSITORY
git branch -M main
git push -u origin main

Pour les modifications suivantes :

git add .
git commit -m "Mise a jour"
git push

9. Lire les erreurs

  • Vérifier le dossier avec pwd ou l'explorateur.
  • Vérifier git status.
  • Vérifier l'URL avec git remote -v.
  • Lire le message Git avant de modifier au hasard.

10. Déploiement

  1. Tester le site localement.
  2. Vérifier les chemins HTML/CSS/JS.
  3. Vérifier les images et données.
  4. Envoyer le projet sur le dépôt.
  5. Activer un hébergement statique adapté.
  6. Ouvrir l'URL publiée et tester les pages.

11. Bon workflow professionnel

git status
git pull
git switch -c ma-fonctionnalite
# coder et tester
git add .
git commit -m "Ajouter ma fonctionnalite"
git push -u origin ma-fonctionnalite

TP

  1. Créer un mini-site de trois pages.
  2. Faire au moins trois commits.
  3. Créer une branche.
  4. Modifier le site puis publier une version fonctionnelle.
  5. Documenter le projet dans README.md.
