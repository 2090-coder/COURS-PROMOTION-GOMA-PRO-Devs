Arduino 13 — GPS / GNSS : comprendre, câbler et programmer

Dans ce chapitre, nous allons partir du principe physique du positionnement jusqu'au programme Arduino complet avec SoftwareSerial et TinyGPSPlus.

1. Objectifs du chapitre

  • Comprendre ce qu'est un GPS et la différence avec GNSS.
  • Comprendre comment un récepteur calcule une position.
  • Comprendre UART, TX et RX.
  • Comprendre les trames NMEA.
  • Installer et utiliser TinyGPSPlus.
  • Comprendre le programme ligne par ligne.
  • Afficher latitude, longitude, altitude, vitesse, satellites, HDOP, date et heure.
  • Générer un lien de position à partir des coordonnées.
  • Savoir diagnostiquer un GPS qui ne donne aucune position.

2. GPS ou GNSS ?

GPS est le nom du système américain de navigation par satellites. GNSS est le terme général qui regroupe les systèmes mondiaux de navigation par satellites, par exemple GPS, Galileo, GLONASS et BeiDou.

Un récepteur GNSS compatible peut donc utiliser plusieurs constellations selon son matériel et sa configuration. Les modules u-blox M8, par exemple, prennent en charge plusieurs constellations et disposent notamment d'une interface UART. citeturn0search2turn0search25

Satellites → signaux radio → récepteur GNSS → calcul de position → données NMEA → Arduino

3. Comment le GPS trouve-t-il notre position ?

Chaque satellite transmet notamment une référence de temps et des informations permettant au récepteur d'estimer le temps de propagation du signal. Le récepteur transforme ces mesures en pseudo-distances.

Avec plusieurs satellites, il résout simultanément sa position et l'erreur de son horloge. Ce n'est donc pas simplement une « triangulation » avec trois points : le temps est essentiel au calcul, et une solution complète de positionnement et de temps nécessite plusieurs mesures satellitaires.

La qualité dépend de la visibilité du ciel, de la géométrie des satellites, des signaux reçus et des conditions radio.

5. Attention à ton « NEO-800L »

Le nom commercial peut correspondre à un module basé sur une famille NEO-8/M8 ou à un clone. Il faut donc vérifier les marquages et la carte réelle avant de fixer la tension d'alimentation.

Important : ne branche pas automatiquement VCC sur 5 V simplement parce que l'Arduino UNO fonctionne en 5 V. Le circuit u-blox M8 lui-même a des limites d'alimentation qui dépendent du modèle, tandis qu'une carte d'extension peut intégrer un régulateur. Vérifie toujours la documentation et le marquage de ton module. citeturn0search2turn0search25

Pourquoi croiser ? TX signifie transmission et RX réception. Le transmetteur d'un appareil doit donc aller vers le récepteur de l'autre.

7. UART : la route des données

Le GPS transmet une suite de caractères sur une liaison série. Dans notre montage, Arduino reçoit ces caractères avec SoftwareSerial.

Dans un réglage courant des modules u-blox M8, l'UART peut être configuré à 9600 bauds, 8 bits, sans parité, 1 bit d'arrêt (8N1). Mais un module clone ou reconfiguré peut utiliser un autre débit : il faut donc vérifier le module réel. citeturn0search24

9600 bauds indique le rythme de transmission. Si Arduino écoute à 9600 alors que le GPS transmet à une autre vitesse, les caractères reçus seront généralement illisibles.

8. Les trames NMEA

Le récepteur peut envoyer des phrases textuelles structurées, appelées trames NMEA. Selon la configuration, on peut rencontrer des messages comme GGA, RMC, GSA ou GSV. Les récepteurs u-blox M8 peuvent transmettre NMEA sur leur interface série. citeturn0search24

Une trame contient plusieurs champs séparés par des virgules. Une application pourrait les analyser manuellement, mais cela devient rapidement complexe. TinyGPSPlus s'occupe de cette analyse pour nous.

10. Le programme complet

#include <SoftwareSerial.h>
#include <TinyGPS++.h>

static const int GPS_RX = 4;
static const int GPS_TX = 3;
static const uint32_t GPS_BAUD = 9600;

SoftwareSerial gpsSerial(GPS_RX, GPS_TX);
TinyGPSPlus gps;

void afficherGPS() {
  if (gps.location.isValid()) {
    Serial.print("Latitude  : ");
    Serial.println(gps.location.lat(), 6);

    Serial.print("Longitude : ");
    Serial.println(gps.location.lng(), 6);

    Serial.print("Maps      : https://www.google.com/maps?q=");
    Serial.print(gps.location.lat(), 6);
    Serial.print(",");
    Serial.println(gps.location.lng(), 6);
  }

  if (gps.altitude.isValid()) {
    Serial.print("Altitude  : ");
    Serial.print(gps.altitude.meters());
    Serial.println(" m");
  }

  if (gps.speed.isValid()) {
    Serial.print("Vitesse   : ");
    Serial.print(gps.speed.kmph());
    Serial.println(" km/h");
  }

  if (gps.satellites.isValid()) {
    Serial.print("Satellites: ");
    Serial.println(gps.satellites.value());
  }

  if (gps.hdop.isValid()) {
    Serial.print("HDOP      : ");
    Serial.println(gps.hdop.hdop());
  }
}

void setup() {
  Serial.begin(9600);
  gpsSerial.begin(GPS_BAUD);

  Serial.println("===============================================");
  Serial.println(" GPS NEO-8 / GNSS + ARDUINO");
  Serial.println(" GOMA PRO Devs | Salomon BENGZ");
  Serial.println("===============================================");
}

void loop() {
  while (gpsSerial.available() > 0) {
    gps.encode(gpsSerial.read());
  }

  if (gps.location.isUpdated()) {
    afficherGPS();
  }
}

11. Explication de #include <SoftwareSerial.h>

#include demande au compilateur d'inclure les déclarations nécessaires d'une bibliothèque.

SoftwareSerial.h permet de créer une liaison série sur certaines broches numériques lorsque l'on ne veut pas utiliser directement le port série matériel principal.

Dans notre exemple, nous voulons conserver Serial pour le moniteur série du PC et utiliser une autre liaison pour le GPS.

12. Explication de #include <TinyGPS++.h>

Cette ligne rend disponibles les classes et méthodes de TinyGPSPlus.

La bibliothèque reçoit les caractères NMEA et transforme les informations complexes en propriétés plus faciles à utiliser, par exemple gps.location.lat() ou gps.speed.kmph(). citeturn0search0turn0search1

13. Explication de SoftwareSerial gpsSerial(4, 3)

SoftwareSerial gpsSerial(4, 3);

Pour SoftwareSerial(RX, TX) :

  • 4 est la broche Arduino qui reçoit les données du GPS.
  • 3 est la broche Arduino qui peut transmettre vers le GPS.

Donc le câblage correspondant est GPS TX → D4 et GPS RX → D3.

14. Explication de TinyGPSPlus gps;

Cette instruction crée un objet nommé gps.

On peut considérer cet objet comme notre « interprète GPS » : nous lui donnons les caractères reçus, et il construit progressivement les informations de navigation.

15. Pourquoi Serial.begin(9600) et gpsSerial.begin(9600) ?

Serial.begin(9600);
gpsSerial.begin(9600);

Ce sont deux liaisons différentes :

  • Serial : Arduino ↔ ordinateur / moniteur série.
  • gpsSerial : Arduino ↔ module GPS.

Les deux peuvent utiliser 9600 dans cet exemple, mais cela ne signifie pas qu'il s'agit du même canal de communication.

16. Comprendre gpsSerial.available()

while (gpsSerial.available() > 0) {
  gps.encode(gpsSerial.read());
}

available() permet de savoir si des données attendent dans le buffer série.

Tant qu'au moins un caractère est disponible, read() lit un caractère. Ce caractère est ensuite envoyé immédiatement à gps.encode().

Idée importante : le GPS envoie un flux continu. Arduino doit donc traiter les caractères régulièrement au lieu d'attendre une phrase complète en une seule fois.

17. Pourquoi gps.encode(gpsSerial.read()) ?

Cette instruction réalise deux opérations :

  1. gpsSerial.read() récupère le prochain caractère reçu.
  2. gps.encode(...) donne ce caractère au parseur TinyGPSPlus.

Répétée des centaines ou milliers de fois, cette opération permet à TinyGPSPlus de reconstruire et d'interpréter les trames NMEA.

18. isValid() et isUpdated()

FonctionIdéeUtilisation
isValid()La donnée disponible est valide.Avant d'afficher une valeur.
isUpdated()Une nouvelle valeur vient d'être traitée.Pour agir lorsqu'une nouvelle position arrive.

Dans notre programme, gps.location.isUpdated() évite d'afficher continuellement la même position lorsque aucune nouvelle position n'a été traitée.

19. Explication de la latitude et longitude

gps.location.lat()
gps.location.lng()

lat() renvoie la latitude et lng() la longitude.

Avec 6 dans Serial.println(..., 6), nous demandons six chiffres après la virgule pour l'affichage.

Attention : afficher six décimales ne signifie pas que le GPS possède réellement une précision de quelques centimètres. La précision réelle dépend du récepteur, des signaux et des conditions de réception.

20. Altitude et vitesse

gps.altitude.meters();
gps.speed.kmph();

meters() demande l'altitude en mètres. kmph() demande la vitesse en kilomètres par heure.

Il faut vérifier isValid() avant d'utiliser ces données.

21. Satellites et HDOP

gps.satellites.value();
gps.hdop.hdop();

Le nombre de satellites donne une indication utile, mais ne suffit pas à lui seul pour juger toute la qualité de la position.

Le HDOP renseigne sur la géométrie des satellites utilisée pour le positionnement. Une valeur plus faible est généralement associée à une meilleure géométrie.

22. Date et heure UTC

gps.date.day();
gps.date.month();
gps.date.year();

gps.time.hour();
gps.time.minute();
gps.time.second();

Les récepteurs GNSS fournissent couramment le temps en UTC. Il faut donc appliquer la différence de fuseau horaire si l'on veut afficher une heure locale.

23. Construire le lien de carte

Serial.print("https://www.google.com/maps?q=");
Serial.print(gps.location.lat(), 6);
Serial.print(",");
Serial.println(gps.location.lng(), 6);

Le programme construit simplement une adresse contenant latitude et longitude. Cela permet de copier les coordonnées dans un service de cartographie.

24. Pourquoi le GPS peut-il ne rien afficher ?

  • Pas de caractères : problème de TX/RX, GND, alimentation ou débit.
  • Caractères illisibles : mauvais débit série probable.
  • Caractères reçus mais pas de position : le module n'a peut-être pas encore obtenu de fix.
  • Fix lent : placer l'antenne dans un endroit adapté avec une vue dégagée du ciel.
  • Valeurs instables : environnement radio, géométrie satellitaire ou qualité du signal.
Règle de diagnostic : d'abord vérifier « est-ce qu'Arduino reçoit des caractères ? », puis « est-ce que TinyGPSPlus les comprend ? », puis « est-ce qu'une position valide est disponible ? ».

25. Diagnostic avec charsProcessed()

if (millis() > 5000 && gps.charsProcessed() < 10) {
  Serial.println("Aucune donnee GPS recue");
}

millis() mesure le temps écoulé depuis le démarrage. Après cinq secondes, si presque aucun caractère n'a été traité, le programme peut signaler un problème de communication.

C'est un diagnostic de communication, pas une preuve que le GPS n'a pas de satellites.

29. Résumé général

  • GPS est une constellation ; GNSS est le terme général pour les systèmes de navigation satellitaire.
  • Le récepteur calcule sa position à partir de mesures de temps et de pseudo-distances.
  • UART transporte les caractères entre le module et Arduino.
  • TX va vers RX et RX va vers TX.
  • NMEA fournit des messages structurés.
  • TinyGPSPlus transforme le flux NMEA en données faciles à exploiter.
  • gps.encode() traite les caractères un par un.
  • isUpdated() est utile pour réagir à une nouvelle position.
  • isValid() permet de vérifier la validité d'une donnée.
  • Latitude et longitude permettent de représenter une position géographique.
  • Un fix satellite et une liaison série fonctionnelle sont deux problèmes différents.
