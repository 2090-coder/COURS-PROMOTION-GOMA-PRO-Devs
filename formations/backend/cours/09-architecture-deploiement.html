WEB BACKEND · CHAPITRE 09

Architecture, API et mise en ligne

Transformer les exercices en une application organisée, testable et préparée pour un hébergement réel.

1. Organisation professionnelle

projet/
├── public/
│   ├── index.php
│   ├── login.php
│   └── logout.php
├── src/
│   ├── Controllers/
│   ├── Services/
│   └── Repositories/
├── config/
├── views/
├── storage/
└── README.md

2. Séparer les responsabilités

  • Controller : reçoit et coordonne une requête.
  • Service : contient une logique métier.
  • Repository : travaille avec les données.
  • View : présente le résultat.

3. API JSON

<?php
header('Content-Type: application/json; charset=utf-8');

echo json_encode([
  'success' => true,
  'message' => 'Bonjour',
  'data' => []
]);

Une API permet à un frontend ou une autre application de communiquer avec le backend.

4. Réponses HTTP

http_response_code(201);

http_response_code(400);

http_response_code(404);

5. Configuration et secrets

Les mots de passe de base de données, clés privées et autres secrets ne doivent pas être commités dans Git. Utiliser une configuration adaptée à l'environnement.

6. Sauvegardes

  • Sauvegarder la base régulièrement.
  • Conserver plusieurs versions lorsque nécessaire.
  • Tester une restauration.
  • Protéger les sauvegardes.

7. Préparer la production

  1. Configurer les variables de production.
  2. Créer la base de données.
  3. Importer le schéma.
  4. Déployer le code.
  5. Activer HTTPS.
  6. Désactiver les affichages d'erreurs détaillés aux visiteurs.
  7. Tester inscription, connexion, sessions, droits et CRUD.

8. Checklist

[ ] Base créée

[ ] Secrets hors Git
[ ] HTTPS actif
[ ] Sauvegarde testée
