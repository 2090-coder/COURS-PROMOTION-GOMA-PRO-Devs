WEB BACKEND · CHAPITRE 09

Architecture, API et mise en ligne

Avant le projet final, on apprend à transformer un petit script en application organisée, testable et prête à être déployée.

1. Séparer les responsabilités

projet/
  public/
  src/
    Controllers/
    Services/
    Repositories/
  config/
  views/
  storage/

L'objectif est d'éviter de mélanger dans une seule page HTML, SQL, authentification et logique métier.

2. API JSON

<?php
header('Content-Type: application/json; charset=utf-8');

echo json_encode([
  'success' => true,
  'message' => 'Bonjour'
]);

Une API permet à un frontend ou à une autre application de communiquer avec le backend à l'aide de requêtes HTTP et de données structurées.

3. Configuration

Les mots de passe de base de données, clés et autres secrets ne doivent pas être placés dans Git. Utilisez des variables d'environnement ou un mécanisme de configuration adapté à l'hébergement.

4. Sauvegardes et erreurs

  • Prévoir des sauvegardes régulières de la base.
  • Conserver les journaux d'erreurs côté serveur.
  • Ne pas afficher les détails internes aux visiteurs.
  • Tester les restaurations de sauvegarde.

5. Mise en ligne

  1. Préparer la configuration de production.
  2. Créer la base sur l'hébergement.
  3. Importer le schéma et les données nécessaires.
  4. Déployer le code.
  5. Configurer le domaine et HTTPS.
  6. Tester inscription, connexion, droits et formulaires.

TP

  1. Transformer votre projet des chapitres précédents en structure organisée.
  2. Créer une petite route JSON.
  3. Déplacer les informations sensibles hors du code.
  4. Écrire une checklist de mise en production.
