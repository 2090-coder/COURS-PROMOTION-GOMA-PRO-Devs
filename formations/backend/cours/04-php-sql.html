WEB BACKEND · CHAPITRE 04

Formulaires, validation et redirections

Un backend devient interactif lorsqu'il reçoit des données du navigateur et décide quoi en faire.

1. Premier formulaire

<form method="post" action="traitement.php">
  <label for="nom">Nom</label>
  <input id="nom" name="nom" required>
  <button type="submit">Envoyer</button>
</form>

2. Lire POST

$nom = trim($_POST['nom'] ?? '');
if ($nom === '') {
    exit('Nom obligatoire');
}
echo htmlspecialchars($nom, ENT_QUOTES, 'UTF-8');

3. GET

GET est souvent utilisé pour des paramètres visibles dans l'URL. POST est adapté à de nombreuses soumissions de formulaires.

$recherche = trim($_GET['q'] ?? '');

4. Validation

$email = trim($_POST['email'] ?? '');
if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    exit('Email invalide');
}

Valider côté serveur même si HTML possède déjà required ou type="email".

5. Redirection

header('Location: merci.php');
exit;

La redirection doit être envoyée avant toute sortie HTTP incompatible avec les headers.

6. Pattern POST/Redirect/GET

  1. Le navigateur envoie POST.
  2. PHP valide et enregistre.
  3. PHP redirige.
  4. Le navigateur effectue un GET sur la page résultat.

7. Formulaire complet

<form method="post" action="traitement.php">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required>
  <label for="message">Message</label>
  <textarea id="message" name="message" required></textarea>
  <button type="submit">Envoyer</button>
</form>

8. Bonnes pratiques

  • Valider les données côté serveur.
  • Ne jamais faire confiance aux données reçues.
  • Échapper les données lors de l'affichage HTML.
  • Utiliser POST pour les opérations qui modifient des données.
  • Rediriger après un traitement réussi.

TP

  1. Créer un formulaire de contact.
  2. Vérifier nom, email et message.
  3. Afficher une erreur si une donnée est invalide.
  4. Afficher une page de confirmation après succès.
  5. Ajouter une redirection.
